# Data Dictionary

## Search result record

The analysis UI uses this TypeScript shape:

| Field | Type | Required | Description |
|---|---|---|---|
| `title` | string | Yes | Search result title/headline |
| `link` | string | Yes | Source URL |
| `confidence` | number | No | Gemini-generated relevance score |

The collection routes return title/link pairs. The AI analysis route enriches them with confidence.

## Competitor candidate record

The competitor discovery UI expects:

| Field | Type | Required | Description |
|---|---|---|---|
| `title` | string | Yes | Candidate competitor name |
| `confidence` | number | Yes in UI type | Gemini-generated candidate relevance metric |

The route also extracts snippets from search results internally, but the final response currently returns the model's candidate array rather than source-level evidence.

## Confidence interpretation

The score is requested on a 0-to-1 scale and displayed as a percentage. It is a heuristic generated by a language model. It is not calibrated, independently evaluated, or guaranteed to be bounded by the route's runtime validation.

## Provenance fields not currently stored

For reproducible research, a future normalized record should consider:
- Provider/source identifier.
- Original query.
- Retrieval timestamp.
- Publication timestamp, when known.
- Canonical URL.
- Original title and snippet.
- AI model identifier and scoring prompt version.
- Confidence score and explanation.
- Human verification status and reviewer notes.

Do not assume these fields exist in the current API response or CSV.
