# Known UI and Product Behavior

This document separates live application functionality from demonstrative or incomplete interface elements.

## Working routes

- `/`: landing page with hero and how-it-works sections.
- `/competitors`: submits a company name to `/api/getcomp` and displays returned candidates.
- `/analysis`: searches for target/competitor relationships, displays paginated links, invokes Gemini scoring, and exports CSV.

## Demonstration or incomplete elements

### Landing page
The landing page currently renders `HeroSection` and `HowItWorks`. `CompetitorFindings` and `CallToAction` are imported but commented out. The hero includes static sample company names and counts. Do not present these sample values as live findings or verified customer evidence.

### Navigation
The shared header links to Home, How It Works, Findings, and Contact anchors. The current landing page does not render every linked section. Some navigation items therefore do not reach a corresponding section.

### Footer
The footer includes placeholder links with `#` destinations, and product links for features not implemented in this repository. They are visual placeholders, not working product pages.

### Demo component
`app/components/analysiscomp/CompetitorFinder.tsx` uses a hard-coded competitor list and a simulated timeout. The current `/analysis` page renders `TargetAnalysis`, not this demo component.

### Findings component
`CompetitorFindings.tsx` contains hard-coded example relationships and source URLs. It is currently not rendered by the landing page. These examples are not generated by the live research APIs.

### Call-to-action component
`CallToAction.tsx` contains a form UI without a configured submission handler. It is not currently rendered by the landing page.

## Recommended product cleanup

1. Remove or clearly label placeholder links and demo content.
2. Ensure every navigation anchor has a rendered target.
3. Add visible loading, empty, and error states to all search experiences.
4. Replace non-semantic clickable containers with keyboard-accessible controls.
5. Confirm static sample relationship claims and URLs before enabling the findings component.
6. Wire or remove forms that currently have no submission behavior.
